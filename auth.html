1. The Problem (Security Gaps)

Two security audit findings (C1, C2) identified gaps in the current system:

C1 — No Authentication on Approval Endpoints

Anyone who can reach POST /api/langgraph/approve/{id} can approve a remediation plan. There's no check for who they are.

C2 — Approver Identity from Request Body

The current code trusts approved_by from the JSON body. A user can type any name they want. There's no server-side identity verification.

What This Means In Practice

Right now, the platform's control_plane.py only has CORSMiddleware. Any HTTP request to /api/* is processed without checking identity or permissions. This middleware module was written to close those gaps but has not been integrated yet.

2. The Solution (JWT + RBAC)

Two-Layer Security
  • JWT (JSON Web Token) — Proves who you are (authentication). The server creates a signed token when you log in. Every subsequent request carries this token.
  • RBAC (Role-Based Access Control) — Proves what you can do (authorization). Your role (viewer, operator, approver, admin) determines which endpoints you can access.

3. The 4 Roles

Role View Incidents Trigger Workflows Approve / Reject Plans Change Config Delete Resources
viewer Yes No No No No
operator Yes Yes No No No
approver Yes Yes Yes No No
admin Yes Yes Yes Yes Yes
Role Hierarchy

Higher roles inherit all permissions of lower roles. An approver can do everything an operator and viewer can do, plus approve/reject.

# From auth.py ROLE_HIERARCHY = { Role.VIEWER: {VIEWER}, Role.OPERATOR: {VIEWER, OPERATOR}, Role.APPROVER: {VIEWER, OPERATOR, APPROVER}, Role.ADMIN: {VIEWER, OPERATOR, APPROVER, ADMIN}, }

Dev Mode Bypass

When ENVIRONMENT=local and AUTH_BYPASS=true (the defaults), the middleware skips JWT validation and grants admin role to every request. This lets developers work without tokens. In production, these env vars must be changed.

5. How JWT Tokens Work

A JWT is three base64-encoded parts joined by dots:

Header.Payload.Signature Header = {"alg": "HS256", "typ": "JWT"} Payload = {"sub": "sam@company.com", "role": "approver", "iat": 1707580800, "exp": 1707584400} Signature = HMAC-SHA256(header.payload, JWT_SECRET)
Why No PyJWT Dependency?

This implementation uses Python's built-in hmac + hashlib modules. This means zero extra dependencies to install. The trade-off: it only supports HS256 (symmetric signing). For production with external identity providers (Okta, Auth0), you'd swap this for PyJWT with RS256 (asymmetric) support.

Token Lifecycle
  • Created: When user logs in, server calls create_jwt(user_id, role)
  • Sent: Browser stores token and sends it as Authorization: Bearer <token>
  • Verified: Middleware calls verify_jwt(token) on every request
  • Expires: After JWT_EXPIRY_SECONDS (default 3600 = 1 hour), token is rejected

6. The Middleware Code Explained

The file provides three ways to use authentication:

Option A — RBACMiddleware (Global, Automatic)

A Starlette middleware that intercepts every /api/* request. No changes needed to individual route handlers. This is the recommended approach.

# What it does for every request: class RBACMiddleware(BaseHTTPMiddleware): async def dispatch(self, request, call_next): # 1. Skip /health, /metrics, /docs # 2. Skip non-/api/ paths # 3. Dev bypass if ENVIRONMENT=local # 4. Extract Bearer token from header # 5. Verify JWT signature + expiry # 6. Attach user to request.state.user # 7. Check endpoint role requirements # 8. Return 401/403 or continue
Option B — get_current_user (Per-Endpoint Dependency)

A FastAPI Depends() injection. Use this when you need the user object inside a specific handler.

from fastapi import Depends @app.post("/api/approve/{id}") async def approve(id: str, user: AuthenticatedUser = Depends(get_current_user)): # user.user_id = "sam@company.com" (from JWT, NOT from body) # user.role = Role.APPROVER # user.has_role(Role.APPROVER) = True if not user.has_role(Role.APPROVER): raise HTTPException(403, "Insufficient permissions")
Option C — @require_role Decorator

A decorator for route handlers. Assumes the middleware already set request.state.user.

@app.post("/api/approve/{id}") @require_role(Role.APPROVER) async def approve(id: str, request: Request): user = request.state.user # Already validated by decorator # Guaranteed to be at least APPROVER role

7. How to Wire It In

Currently, control_plane.py only adds CORS. To enable auth:

Current Code (NO auth)
# agents/servicenow_agent/src/api/control_plane.py — create_app() app = FastAPI(title="AI Agent Platform", lifespan=lifespan) app.add_middleware( CORSMiddleware, allow_origins=["*"], allow_methods=["*"], allow_headers=["*"], ) # <-- No RBACMiddleware. Every /api/ request is unauthenticated.
What Needs to Change (2 lines)
# Add this import at the top: from agents.servicenow_agent.src.middleware import RBACMiddleware # Add this line AFTER CORSMiddleware: app.add_middleware(RBACMiddleware) # That's it. All /api/* endpoints are now protected. # /health, /metrics, /docs remain open. # Dev mode still bypasses auth (ENVIRONMENT=local).
Endpoint → Role Mapping

The middleware uses this map to decide the minimum role for each endpoint:

ENDPOINT_ROLES = { "GET /api/incidents": Role.VIEWER, "GET /api/langgraph/incidents": Role.VIEWER, "POST /api/langgraph/approve/": Role.APPROVER, # Closes C1 "POST /api/langgraph/reject/": Role.APPROVER, "POST /api/langgraph/workflow": Role.OPERATOR, "POST /api/v2/data-agent/": Role.OPERATOR, "PUT /api/config": Role.ADMIN, "DELETE /api/": Role.ADMIN, }
